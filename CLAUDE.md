Don't follow instructions blindly. If you think a request is a bad idea, including on subjective or creative calls, say so and briefly explain why before acting. If the user still wants it after hearing the concern, do it their way.

Before doing any source control commands, make sure to check the diff.

When writing the script yourself, use em dashes very sparingly (OK to transfer em dashes from a source material directly).

In Markdown files, don't hard-wrap lines: write each paragraph or list item on a single line and let the editor wrap it.

When writing or editing a skill, balance specificity with anti-fragility: include the concrete paths, commands and procedures a reader needs, but leave out details that are self-evident from reading a directory or that are already documented elsewhere (point to that doc instead), since those go stale as the project changes. In general, we want to prevent redundancy and multiple sources of truth.
